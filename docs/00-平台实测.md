# 百度地图 JSAPI WebGLLayer 实测结论

所有结论均在本机实测得出（Chrome 系统版 + Metal/M2），非文档推测。

## 1. 必须用 JSAPI 4.0

- `https://api.map.baidu.com/api?v=4.0&type=webgl&ak=...` 才有 WebGLLayer 体系。
- 默认的 `v=1.0&type=webgl` 内核没有这套扩展接口，`BMap.WebGLCustomLayer` 为 `undefined`。
- 4.0 下 `window.BMap === window.BMapGL`，两套命名同时可用。

## 2. WebGLLayer 类族

原型链实测：

```
WebGLCustomLayer(K) → WebGLLayer(bL) → Object
ThreejsLayer(b2)    → WebGLLayer(bL) → Object
DeckglLayer(ed)     → WebGLLayer(bL) → Object
PointLayer(nr)      → FeatureVisualLayer(mQ) → WebGLLayer(bL)
```

- `BMap.WebGLLayer` **没有对外导出**（4.0 只导出 `WebGLCustomLayer` / `ThreejsLayer` / `DeckglLayer` / `PointLayer` 等）。
- 取基类要沿原型链找「自己的原型上同时有 `onAdd`/`render`/`getMVPMatrix` 且 `isWebGLLayer` 为真」的那一层，即 `bL`。
- 生命周期：`onAdd(map, gl)` → `preRender` → `render(gl, mvp)` → `afterRender` → `onDestroy`。

## 3. 渲染回调与坐标系

- `render(gl, mvp)`，第二参实测是 **Float64Array(16)**。
- GL 上下文是 **WebGL1**（`WebGLRenderingContext`）。
  可用扩展：`ANGLE_instanced_arrays`、`OES_vertex_array_object`、`OES_element_index_uint`、`EXT_disjoint_timer_query`。
- 矩阵作用于**相对墨卡托坐标**：`rel = BD09MC(lnglat) - BASE_MC`，
  `BASE_MC = [12069475.280738307, 3929271.1724863998]`，实测为固定常量，**不随平移漂移**。
- 顶点数据放 `Float32Array` 完全够用：最坏情况（乌鲁木齐）`rel` 量级约 3.3e6，
  float32 尾数精度约 0.25 m，在 zoom 19 也只有约 0.1 px 误差。

实测对齐（自算 rel + 内置 `u_mvpMatrix` vs `map.pointToPixel`）：

| 场景 | 最大像素偏差 |
|---|---|
| zoom 12 / 平移 | < 0.5 px |
| zoom 19 | < 0.5 px |
| heading 40° | < 0.5 px |
| tilt 55° | < 0.5 px |

## 4. WebGLCustomLayer 的两条路径

| | 默认（安全模式） | `unsafeGL: true` |
|---|---|---|
| `ctx.gl` | 与原生等价（实测标记为 raw） | 原生 |
| 保存/恢复 GL 状态 | 框架自动，且会清空底图 painter 的 program 缓存 | 框架仍做，但提示无法穷举视口/FBO/pixelStorei |
| 实例化/VAO/自建缓冲区 | 可用 | 可用 |

**结论：用默认模式。** 它会保存状态机、纹理绑定、VAO、FBO、视口，并在结束时
`programMgr.currentProgram = null`，不会污染底图。

## 5. 内置 uniform / 接口（onRender 的 ctx）

内置 uniform：`u_mvpMatrix`、`u_opacity`、`u_zoom`、`u_time`、`u_resolution`、
`u_pixelRatio`、`u_unitsPerPixel`、`u_center`、`u_heading`、`u_tilt`。

ctx 可用方法：`setUniform` / `setAttribute` / `draw` / `drawIndexed` /
`getMVPMatrix` / `projectToLayer` / `getUnitsPerPixel` / `getSize` /
`getPixelRatio` / `getZoom` / `getHeading` / `getTilt` / `setRenderState`。

注意：内置 `attributes` 通道是**一次性上传**的静态数据，做不了增量更新。
海量动态数据必须在 `onRender` 里自建缓冲区 + `bufferSubData` 局部更新。

## 6. 冷启动开销

GL 模块（`visual.js`）是懒加载的：页面上出现 canvas 到首帧约 6 s（本机 headless 实测，
含网络）。所以「首屏可用」和「数据就绪」必须解耦，这也正是流式渲染的价值所在。

## 7. 自动化环境会被识别并降级（影响性能测试）

在 Playwright / Puppeteer / 无头 Chrome 中打开地图（`navigator.webdriver = true`、UA 含 `HeadlessChrome`、或有调试协议连接）：

- 矢量瓦片能正常下载（HTTP 200，单块数百 KB），但解码 Worker 收到 `loadTileData` 后**不再回复**，画面只有灰色占位网格；
- 反爬脚本（`abclite`）持续占用大量主线程；
- 不加任何图层的空地图只有 **0.5–3 FPS**。

同一页面在普通 Chrome / Safari 中为 **60 FPS**。因此性能数据必须在普通浏览器中采集（本项目用 `tools/bench/chrome-real.sh`、`safari-real.sh`，结果由页面 POST 回服务器）。
CPU 采样可用远程调试端口，但只启用 `Profiler` 域、不启用 `Runtime` 域（`tools/bench/rawprof.mjs`）。

## 8. 相机控制

- `map.setHeading()` / `setTilt()` 默认带过渡动画；若随后每帧调用 `map.setCenter(…, { noAnimation: true })`（如镜头跟随），动画会被打断、角度停在原值。需要立即生效时传 `{ noAnimation: true }`。
- `centerAndZoom()` 会重置倾斜角，倾斜要在其后设置。
